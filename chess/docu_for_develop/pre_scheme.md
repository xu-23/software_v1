# 桌面版战棋游戏开发预方案

## 1. 方案定位

本方案以 Windows 版 Godot 4 为核心开发工具，以 WSL Linux + VS Code 作为代码编辑、版本管理和辅助脚本环境，目标是完成一款可在桌面端运行的 2D 回合制战棋游戏。

推荐技术路线：

```text
Windows 版 Godot 4
+ VS Code Remote WSL
+ WSL2 Linux 文件系统
+ Git 版本管理
+ Godot GDScript
+ 桌面端导出 Windows/Linux
```

该方案优先追求：

- 快速做出可玩原型
- 工程结构清晰
- 开发环境稳定
- 后续可扩展角色、职业、技能、装备、剧情和关卡

第一阶段目标不是直接制作大型商业战棋，而是先完成一个具备完整闭环的桌面版原型。

## 2. 开发目标

### 2.1 最小可玩版本

最小可玩版本需要包含：

- 10x10 或 12x12 方格地图
- 至少 2 个玩家单位
- 至少 3 个敌方单位
- 单位选择
- 移动范围显示
- 点击格子移动
- 攻击范围显示
- 普通攻击
- 敌方简单 AI
- 玩家回合与敌方回合切换
- 胜利与失败判定
- 基础 UI：单位信息、回合状态、行动菜单

### 2.2 桌面版目标

首个桌面版目标平台：

- Windows 10/11 桌面版

可选导出平台：

- Linux 桌面版
- Web HTML5 版，后续考虑

当前阶段不建议优先做：

- 在线多人
- 手机端适配
- 复杂联网账号系统
- 大规模剧情分支
- 商业级美术管线

## 3. 开发环境方案

### 3.1 推荐环境

主机环境：

- Windows 10/11
- WSL2
- Ubuntu 或其他常见 Linux 发行版
- VS Code
- VS Code Remote WSL 插件
- Windows 版 Godot 4.x

推荐项目位置：

```text
/home/xu/projects/tactics-game
```

Windows 版 Godot 可通过以下路径打开 WSL 项目：

```text
\\wsl.localhost\Ubuntu\home\xu\projects\tactics-game
```

如果 WSL 发行版名称不是 `Ubuntu`，路径中的 `Ubuntu` 需要替换成实际名称。

### 3.2 为什么使用 Windows 版 Godot

Windows 版 Godot 的优势：

- 图形界面更稳定
- 编辑器性能通常更好
- 鼠标、键盘、窗口、显卡兼容性更少出问题
- 导出 Windows 桌面版更自然

WSL 的职责：

- 保存源码
- 使用 Git
- 编写脚本
- 处理 JSON、CSV、配置和数据文件
- 用 VS Code 编辑代码
- 后续可接入自动化测试或资源处理脚本

### 3.3 当前 WSL + VS Code 图形呈现说明

在 Windows 11 + WSL2 中，WSLg 通常支持 Linux 图形程序。但本方案不依赖 WSLg。

本方案的图形呈现方式是：

- Godot 编辑器在 Windows 中运行
- 游戏预览窗口由 Windows 版 Godot 打开
- VS Code 通过 Remote WSL 编辑同一个项目目录

因此，即使 WSL GUI 支持不完善，也不影响主要开发流程。

## 4. 存储与内存估算

### 4.1 本地开发磁盘空间

建议为项目和开发缓存预留：

| 项目 | 估算空间 |
|---|---:|
| WSL 基础环境 | 2-5 GB |
| Godot 编辑器 | 100-300 MB |
| 项目源码 | 50-300 MB |
| 美术占位资源 | 100 MB-1 GB |
| 音效与音乐 | 100 MB-1 GB |
| 导出包与缓存 | 1-5 GB |
| Git 历史 | 100 MB-2 GB |

建议预留：

```text
最低：10-20 GB
舒适：30-50 GB
```

如果后续引入大量角色立绘、动画、音乐、语音，项目资源可能增长到 5-20 GB。

### 4.2 运行内存

开发时推荐内存：

| 场景 | 估算内存 |
|---|---:|
| VS Code Remote WSL | 500 MB-2 GB |
| Godot 编辑器 | 500 MB-2 GB |
| 游戏预览 | 100-500 MB |
| 浏览器、素材工具、其他程序 | 1-4 GB |

建议配置：

```text
8 GB RAM：可以开发简单原型
16 GB RAM：较舒适
32 GB RAM：适合同时开素材工具、浏览器和较大项目
```

### 4.3 是否需要生产服务器

单机桌面战棋游戏不需要 Linux 生产服务器。

只有以下功能需要服务器：

- 在线多人对战
- 云存档
- 排行榜
- 用户账号
- 关卡分享
- 远程配置

如果后续需要轻量后端，初期服务器可以从以下规格开始：

```text
1 vCPU
1 GB RAM
10-20 GB 磁盘
```

但本预方案默认不建设后端。

## 7. 核心系统设计

### 7.1 地图系统

地图以方格 TileMap 为基础。

每个格子包含：

- 坐标
- 地形类型
- 移动消耗
- 是否可通行
- 防御加成
- 闪避加成，可选

第一版地形建议：

- 平地
- 草地
- 森林
- 山地
- 水域
- 墙体

### 7.2 单位系统

单位基础属性：

- 名称
- 阵营
- 职业
- 等级
- HP
- 攻击
- 防御
- 移动力
- 攻击距离
- 当前坐标
- 是否已行动

第一版不建议加入过多属性。命中、暴击、速度、魔法、抗性可以后续扩展。

### 7.3 回合系统

基础流程：

```text
玩家回合开始
-> 玩家选择单位
-> 移动
-> 攻击或待机
-> 所有玩家单位行动结束
-> 敌方回合开始
-> 敌方 AI 依次行动
-> 回到玩家回合
```

### 7.4 移动与寻路

建议：

- 使用 BFS 计算移动范围
- 使用 A* 计算具体移动路径
- 暂时不考虑 Z 轴高度
- 暂时使用正方形网格，不做六边形网格

### 7.5 战斗系统

第一版战斗公式：

```text
伤害 = max(攻击方攻击 - 防御方防御, 1)
```

后续可扩展：

- 命中率
- 暴击率
- 反击
- 武器克制
- 技能触发
- 属性伤害

### 7.6 敌方 AI

第一版 AI 逻辑：

```text
寻找最近的玩家单位
如果当前可攻击，则攻击
否则移动到距离目标最近的可达格
如果移动后可攻击，则攻击
否则待机
```

第二版可扩展：

- 优先击杀低血量目标
- 避开玩家攻击范围
- 集火同一目标
- 根据地形选择站位
- 防守型、突击型、治疗型 AI

### 7.7 关卡系统

每个关卡建议包含：

- 地图文件
- 玩家出生点
- 敌人出生点
- 敌人配置
- 胜利条件
- 失败条件
- 剧情触发点

第一版胜利条件：

```text
击败所有敌人
```

第一版失败条件：

```text
所有玩家单位阵亡
```

## 8. 数据管理方案

早期建议使用 Godot Resource 或 JSON。

如果偏向可读、可编辑，使用 JSON：

```text
data/units/player_units.json
data/units/enemy_units.json
data/maps/map_001.json
data/chapters/chapter_001.json
```

如果偏向 Godot 编辑器集成，使用 Resource：

```text
UnitData.tres
ClassData.tres
SkillData.tres
MapData.tres
```

推荐策略：

```text
第一阶段：JSON
第二阶段：稳定后迁移到 Resource 或保留 JSON 管线
```

## 9. 美术和音频策略

第一阶段使用占位资源：

- 简单方块角色
- 免费 TileSet
- 简单 UI 图标
- 免费音效

建议不要在第一阶段投入大量美术成本。优先验证：

- 操作是否顺
- 回合逻辑是否清晰
- 地图是否有策略性
- AI 是否能形成基本压力

可选素材来源：

- Kenney 免费素材
- itch.io 免费或低价战棋素材包
- OpenGameArt
- 自制占位图

## 11. 主要风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 系统设计过早膨胀 | 高 | 第一版只做移动、攻击、回合、胜负 |
| 美术资源不足 | 高 | 使用占位图和免费素材，玩法验证优先 |
| AI 开发复杂 | 中 | 第一版使用最近目标追击 AI |
| WSL 路径访问慢 | 中 | 小项目可接受；大型资源可考虑放 Windows 目录 |
| Godot 与 WSL 文件监听异常 | 中 | 必要时重启 Godot 或手动刷新资源 |
| JSON 数据结构混乱 | 中 | 从第一天保持字段规范 |
| 导出配置出错 | 低到中 | 里程碑 0 后尽早测试一次导出 |

## 14. 需要进一步确认的问题

以下问题会影响后续详细设计：

1. 游戏更接近哪一种战棋？
   - 火焰纹章式方格战棋
   - 皇家骑士团式等距战棋
   - Into the Breach 式小地图解谜战棋
   - 其他

2. 画面风格倾向是什么？
   - 像素风
   - 手绘 2D
   - 简洁棋盘风
   - 暂时无所谓，先占位

3. 操作方式是否只考虑鼠标？
   - 只鼠标
   - 鼠标 + 键盘快捷键
   - 未来支持手柄

4. 第一版是否需要剧情和对话？
   - 不需要，先做战斗
   - 需要简单开场和胜利对话
   - 需要完整剧情章节

5. 是否需要我继续创建项目骨架？
   - 只写方案
   - 创建 Godot 项目目录结构
   - 创建第一版 Godot 原型代码
