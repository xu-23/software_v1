## 3. 版本目标与玩家流程

```text
启动 -> 六关选择 -> 每关以 3 名己方对抗 6-9 名敌人
战斗 -> 根据单位强项编队走位 -> 普通敌人形成数量压力，精英敌人形成重点威胁
移动 -> 实际路径经过隐藏机遇 -> 立即获得效果 -> 该机遇永久从本局移除
Menu -> Encyclopedia -> 查看全部 8 种己方和 10 种敌方的中文名称、数值与敌方级别
```

## 7. 机遇

### 7.1 类型

| ID | 中文名 | 所在地形 | 一次性效果 |
|---|---|---|---|
| forest_fruit | 水果 | Forest | 当前 HP +1，不超过最大 HP |
| hill_iron | 精铁 | Hill | 当前护盾 +1 |
| swamp_mire | 泥沼 | Swamp | 当前护盾 +1 |
| plain_supplies | 补给 | Plain | 当前 HP +2，不超过最大 HP |

### 7.2 运行规则

- 机遇是地图格上的隐藏一次性实例，不是新地形，不改变通行、移动消耗、高度或攻击规则。
- 棋盘不绘制机遇图标；悬停未触发格也不泄露机遇信息。
- 玩家和敌方单位都可触发。移动路径从起点后的第一格开始逐格检查，中间格和终点均可触发。
- 触发时先移除实例再结算效果；即使 HP 已满导致实际恢复为 0，机遇仍消失。
- 同一路径可依次触发多个机遇；同一实例在本局只能触发一次。
- 战斗日志使用中文单位名、机遇名和数值变化；`last_action` 记录本次移动的全部机遇事件。
- Restart 重新读取地图并恢复全部机遇；分段移动、敌方移动与既有元素落点能力继续正常工作。

### 7.3 数据与接口

- 新增 `data/opportunities/opportunity_defs.json` 保存 `id`、`name`、`terrain_ids`、`effect` 和正整数 `amount`。
- 地图新增可选 `opportunities` 数组，每项保存唯一实例 `id`、`opportunity_id` 和 `[x,y]` 位置。
- 新增 `BattleOpportunityState.setup()`、`apply_path()`、`has_at()` 和 `remaining_count()`，作为消耗状态与效果结算的唯一来源。
- 数据校验拒绝未知类型、重复 ID/坐标、越界、不可通行格、地形不匹配和非正数效果。

## 11. 验收标准

1. `pre_v0.1.5.md` 未修改，`chess_v0.1.4` 快照保持原样且可恢复。
2. 3 个新己方和 6 个新敌方具备不同定位、中文名称和可用定义。
3. 全部敌人具有合法普通/精英级别，百科和战斗信息可见中文级别。
4. 六关均为 3 名己方、6 至 9 名敌方、至少 1 名精英，部署并集覆盖全部单位种类。
5. 两张新地图尺寸在 10x10 至 14x14 内且可正常完成战斗。
6. 四类隐藏机遇沿实际路径一次性触发，双方、Restart 和日志行为符合第 7 节。
7. Windows Godot 导入退出码 0，完整自动化不少于 240 项且失败数为 0。
8. 1100x720 图形检查无空白、重叠、裁切、不可访问关卡或不可读文本。
9. README 给出纯 Windows 最少软件包、获取方式和从包目录开始的相对启动路径。
10. README、规则参考、结构、数据格式、测试记录和最终报告与实现一致。
11. 技术完成后 Windows Godot 编辑器和当前游戏均启动，状态为“技术完成，待试玩评价”。

## 12. 实施默认项

- “不少于”按最小增量执行：新增 3 个己方名称和 6 个敌方名称。
- 普通/精英比例按综合战斗价值评估，不要求每一个原始字段分别严格乘以 `2/3` 或 `5/3`。
- 机遇对双方生效、隐藏且不影响 AI 选路；AI 不主动感知隐藏机遇价值。
- HP 恢复不超过最大 HP，护盾增长不设上限；机遇无论实际增量是否为 0 都会消失。
- 不新增主动技能按钮、掉落选择、随机机遇生成、机遇动画或独立美术资源。
- 纯 Windows 试玩优先采用 Godot 编辑器运行源码包；缺少导出模板时不承诺独立 EXE。
