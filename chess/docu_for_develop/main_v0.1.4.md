## 4. 战斗界面中文化

### 4.1 中文化范围

- 地形信息：地形名称、坐标、通行状态、高度、移动消耗、路径消耗和剩余移动力。

- `player_units.json`、`enemy_units.json` 中的英文标准名称保持不变，数值覆盖继续使用英文名称作为键。

## 5. 单位数值覆盖接口

### 5.1 可修改字段

| 外部字段 | 运行时字段 | 约束 |
|---|---|---|
| `max_hp` | 最大/初始 HP | 整数，至少 1 |
| `shield` | 基础/初始护盾 | 整数，至少 0 |
| `attack` | 攻击 | 整数，至少 0 |
| `move_range` | 每回合移动力 | 整数，至少 0 |

`name`、阵营、类型、职业、射程、真实伤害、特殊属性、能力和资源路径均不可通过该接口修改。

### 5.2 配置入口

新增 `data/units/unit_stat_overrides.json`：

```json
{
  "units": {
    "Vanguard": {"max_hp": 20, "shield": 7, "attack": 6, "move_range": 4}
  }
}
```

- 键使用单位标准英文 `name`，不使用实例 ID。
- 未配置的单位和未填写的允许字段继续使用原始单位 JSON 数值。
- 同名单位一次覆盖全部实例定义，例如 `Raider` 同时作用于 enemy_001、enemy_002 和 enemy_004。
- 空 `units` 对象表示不覆盖任何数值，v0.1.4 默认保持 v0.1.3 数值。

### 5.3 代码接口

新增 `UnitStatOverrides`：

```gdscript
static func apply_to_data(data: Dictionary, override_data: Dictionary) -> Dictionary
static func apply_to_definitions(definitions: Array, unit_name: String, values: Dictionary) -> Dictionary
static func validate(override_data: Dictionary, known_names: Dictionary) -> Array[String]
```

- `apply_to_data` 返回深拷贝，不修改加载器刚读取的原始对象。
- `apply_to_definitions` 供代码和测试对指定定义集合应用一次内存覆盖，并返回是否成功、修改数量与错误。
- 加载器在单位 JSON 读取后、完整数据校验前应用配置覆盖。
- 非允许字段、未知单位名、错误类型或越界数值会形成校验错误并阻止关卡启动。

### 5.4 修改后的生效方式

1. 修改 `data/units/unit_stat_overrides.json` 中目标单位的四项允许数值。
2. 保存文件。
3. 在游戏中 Restart 当前关卡，或返回 Levels 后重新进入关卡。
4. 新关卡加载时覆盖基础定义；新单位以覆盖后的 HP/护盾/攻击/移动值创建。
5. Encyclopedia 重新启动项目后读取同一份覆盖结果并显示新数值。

进行中的单位不热更新；修改后必须重新加载关卡。配置错误会在 Godot 输出中列出并拒绝启动关卡。

## 6. 职业图标

- 棋盘单位圆形图标继续显示名称缩写。
- `soldier` 在头像右上角显示深色圆底的小剑线稿。
- `raider` 在头像右上角显示深色圆底的小马头剪影。
- `archer` 在头像右上角显示深色圆底的小弓线稿。
- `archer` 同时在头像左下角显示攻击射程数字。
- 标识随棋格尺寸缩放，不能遮挡名称缩写、护盾环或 HP 条；已行动变暗时仍可辨认。
- 职业到标识的映射由统一接口提供，未知职业不绘制标识。

## 7. 第四关

### 7.1 关卡定义

| 条目 | 内容 |
|---|---|
| ID | `stage_004` |
| 名称 | `Shattered Frontier` |
| 难度 | `Very Hard` |
| 地图 | 12x12，固定种子程序生成 |
| 玩家/敌人 | 4/6 |
| 玩家 | Vanguard、Archer、Verdant Guard、Earth Warden |
| 敌人 | Raider x2、Marksman、Raider、Sentry、Flamecaster |

### 7.2 生成规则

- 新增 `ProceduralMapGenerator.generate(spec, seed_override := -1)`。
- `map_004.json` 保存尺寸、固定种子、地形配额、边界配额和受保护出生点，不直接保存最终二维地图。
- 默认固定种子为 `104014`；相同配置和种子必须生成完全相同的 tiles 与 edges。
- 生成器使用独立 `RandomNumberGenerator`，不改变全局随机状态。
- 出生点及其基础出口保持 Plain；Water/Mountain 放置不得切断双方出生区与主战区的可通行连接。
- 地图包含全部六种地形，且至少 20 Forest、12 Hill、8 Swamp、8 Water、6 Mountain、8 River、8 Cliff。
- Cliff 放置后仍须保留双方到主战区的可移动路线；边界 ID 唯一且端点相邻。
- 生成结果进入既有地图与关卡校验器，失败时关卡不得启动。

### 7.3 关卡选择布局

- 四张关卡卡片使用 2x2 网格，1100x720 下完整显示且不横向溢出。
- 第一至第三关内容与顺序不变，第四关追加在末尾。

## 8. 状态与兼容规则

- Restart 重新生成相同种子的第四关并恢复初始单位数值。
- Levels、Menu、Encyclopedia、AI generation 隔离与输入锁保持原行为。
- 数值覆盖同时作用于全部关卡和 Encyclopedia，不修改历史源数据文件。
- 第一至第三关地图、出生点、能力与胜负条件保持不变。

- 参考图片不是游戏界面且含个人证件信息，不作为项目资源、不复制到项目、不记录其中内容。
